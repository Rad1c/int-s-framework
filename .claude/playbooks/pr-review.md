# Pull Request Review

Use this playbook to review a change for correctness and risk.

1. Read the goal, acceptance criteria, and changed files.
2. Trace affected behavior beyond the diff where necessary.
3. Check correctness, regressions, security, data, operations, and tests.
4. Report only actionable findings supported by evidence.
5. Rank findings by impact and cite the exact file and location.
6. State whether the change is ready, blocked, or needs clarification.

Prioritize defects over style preferences. If no defects are found, say so and note any verification gaps.
