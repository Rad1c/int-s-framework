# Knowledge Base

Durable, verified knowledge about the project the scaffold is used on: what is true, what bit us,
and why things are the way they are.

Two sinks are always present:

- `gotchas.md` — non-obvious failures: surprise, cause, fix.
- `decisions.md` — choices between real alternatives, and what was rejected.

Everything else is domain files, added only when a project has verified information to preserve.
Organize by domain, keep entries short, and link to source files instead of restating them.

Do not:

- duplicate documentation maintained elsewhere;
- store assumptions as facts — write `TBD` instead;
- store secrets, credentials, or sensitive production data;
- create placeholder documents without real content.
